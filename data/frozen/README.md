Two files live here. They are **data, not code**, and they are committed
because the manuscript figures were produced from them and they cannot be
regenerated byte-identically.

## Why they are frozen rather than regenerated

Three reasons, in order of importance.

**1. They were built against Ensembl release 114, and the pipeline is now
pinned to 115.** The original notebook called
`useEnsembl(biomart = "genes", dataset = "rnorvegicus_gene_ensembl", version = 114)`.
`scripts/R/01_transcriptome_metadata_annotation.R` connects instead to
`https://sep2025.archive.ensembl.org`, which is release 115 — the release that
matches `Rattus_norvegicus.GRCr8.115.gtf`, the project's annotation lock.

That change is safe for coordinates: **releases 114 and 115 are both GRCr8**
(113 and earlier are mRatBN7.2), so nothing shifts position. But gene names and
biotypes do move between releases, and those feed Figure 2B's class counts and
the annotated-vs-novel lncRNA split. Regenerating would therefore change
published numbers.

**2. The committed notebook is not exactly the code that produced them.**
The `.Rhistory` of the original analysis shows the session that generated
`run_full_analysis(config, ensembl, tx_attributes, exon_attributes)` — four
arguments. The committed `.qmd` defines the function with three. In the
earlier version exon coordinates came from a second biomaRt round-trip; in the
committed version they come from the GTF. So an intermediate variant produced
the shipped files, and that variant was not preserved.

**3. Their upstream chain has a reconstructed step.** R01 depends on bash
stages 09b–09e, and 09b is itself a reconstruction (see `docs/OPEN_ISSUES.md`
§4.1). Regenerating these tables would propagate that uncertainty into
Figure 2B.

## Who reads them

- `scripts/R/06_transcriptome_overview.R` — Figure 2B (both files)
- `scripts/R/22_circRNA_cross_reference.R` — maps mRNA IDs to symbols (`meta_ann` only)

Both resolve through `read_frozen()` in `scripts/R/lib/io.R` by default. Pass
`--meta-ann` / `--meta-novel` to use freshly generated R01 output instead.
